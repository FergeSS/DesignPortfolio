# Портфолио из Яндекс Диска

Простой статический сайт: скрипт читает публичную папку «РаботыСайт», скачивает изображения и TXT, затем создаёт главную и отдельную страницу каждого проекта. На сайте нет запросов к Диску: тексты и изображения размещаются вместе с сайтом. Node.js 22 или новее, внешних npm-зависимостей нет.

## Запуск

```sh
npm ci
npm run dev
```

Открыть http://127.0.0.1:4173. Остановить сервер — Ctrl+C.

- `npm run sync` — загрузить актуальные проекты с Диска в `.cache/`.
- `npm run build` — собрать `dist/` из последней успешной копии без доступа в интернет.
- `npm run refresh` — синхронизировать и, только при успехе, собрать сайт.
- `npm run dev` — проверить Диск при запуске, собрать сайт и открыть его локально. Затем проверять Диск каждые 24 часа, пока сервер работает. При недоступности Диска продолжает показывать предыдущую успешную сборку, если она есть.
- `npm run preview` — показать готовый `dist/` без синхронизации и автоматических проверок, например без интернета.
- `npm test` — проверить загрузку, пагинацию, UTF-8, страницы, сохранность копии при ошибках.

## Папки на Диске

Ссылка уже записана в `portfolio.config.json`. Корень ссылки — сама папка «РаботыСайт», дополнительная папка «Работы» внутри не нужна.

```text
РаботыСайт/
├── Пример1/
│   ├── info.txt
│   ├── cover.jpg
│   ├── 01.jpg
│   └── 02.png
├── Пример2/
│   ├── info.txt
│   └── cover.webp
└── Черновики/             ← полностью игнорируется
```

Названия папок могут быть русскими и содержать пробелы. Одна папка первого уровня — одна работа. Файлы проекта лежат непосредственно внутри неё; вложенные папки проекта не обходятся. Папки `Черновики`, `Drafts` и начинающиеся с точки игнорируются. Файлы в корне тоже игнорируются.

Пустые папки видны на сайте как заготовки с надписью «Нет материалов». Если `info.txt` отсутствует, названием становится имя папки. Замечания доступны по ссылке «Отчёт о загрузке» внизу главной.

## info.txt

Скопируй `examples/info.txt`, сохрани в **UTF-8** и загрузи в папку проекта:

```text
Название: Айдентика кофейни «Зерно»
Категория: Брендинг
Год: 2026
Порядок: 1
Адрес: zerno
Публиковать: да

Описание:
Текст проекта.

Ещё один абзац.
```

Все поля необязательны. Если указываешь поле, пиши его название как в примере. Метаданные идут **до `Описание:`**, всё после этой строки считается описанием. HTML отображается как обычный текст. Порядок — целое число, меньшие числа выше; без поля работа получает 9999. При одинаковом порядке работы сортируются по названию. Категории автоматически становятся фильтрами на главной.

Для совместимости можно использовать `info.docx` с теми же полями: читается основной текст документа Word, оформление не переносится. DOCX, переименованный в `info.txt`, тоже распознаётся по содержимому; в отчёте появится подсказка. В папке должен быть только один файл описания: `info.txt` или `info.docx`. Старый бинарный `.doc`, RTF и произвольные ZIP не поддерживаются.

Если в файле вообще нет полей из примера, весь текст становится описанием, а название берётся из имени папки. Так можно начать с обычного текста и добавить поля позже.

`Адрес` — уникальные строчные латинские буквы, цифры и дефисы. Например, `zerno` создаёт страницу `projects/zerno/`. Без адреса используется стабильный идентификатор, полученный из пути папки; переименование папки изменит такой адрес. Чтобы ссылки сохранялись при переименовании, укажи `Адрес` явно. Также принимается поле `Slug`.

`Публиковать: нет` полностью исключает работу из сайта, JSON и отчёта. Публичная ссылка на сам Диск при этом всё равно даёт доступ к его содержимому: для приватных черновиков держи папку вне «РаботыСайт».

## Изображения

Поддерживаются JPG, JPEG, PNG, WebP, GIF, AVIF. Один файл `cover` с любым из этих расширений — обложка, остальные идут по имени с учётом чисел: `01`, `02`, `10`. Обложка тоже отображается в галерее проекта. Если `cover` отсутствует, для карточки используется первое изображение. Клик по изображению открывает увеличенный просмотр; Escape закрывает его.

Сейчас изображения копируются в исходном размере, **без сжатия и конвертации**. Для каркаса стоит загружать подготовленные веб-изображения. Лимит одного файла — 100 МиБ, меняется через `maxFileBytes` в конфиге. Скачанные изображения проверяются по размеру и MD5 от Диска; неизменившиеся файлы локально повторно не скачиваются. Неиспользуемые изображения в `.cache/` могут оставаться, но в `dist/` попадают только текущие опубликованные материалы.

## GitHub Pages

Workflow `.github/workflows/pages.yml` готов для ветки `main`:

1. Отправить проект в репозиторий GitHub.
2. В **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**.
3. Запустить **Actions → Update portfolio and deploy Pages → Run workflow** или сделать push в `main`.

После подключения GitHub сайт обновляется **раз в сутки, в 04:17 по Москве (01:17 UTC)**. Push в `main` и ручная кнопка Run workflow тоже запускают обновление. Запуски по расписанию могут задерживаться; в публичных репозиториях расписание отключается после 60 дней без активности. Настройка workflow сама по себе не публикует текущие локальные файлы — нужен push.

Открытая страница сама подхватывает новую опубликованную версию примерно в течение минуты. Для этого браузер читает маленький файл `site-version.json` с самого сайта; к Яндекс Диску посетители не обращаются. Если изменилось только время проверки, страница не перезагружается. Во время просмотра увеличенного изображения обновление откладывается. Если текущий проект удалён, браузер возвращается на главную.

Таким образом, достаточно добавлять и редактировать материалы на Диске: после ближайшей ежедневной проверки сайт обновится автоматически. Для срочного обновления локально можно выполнить `npm run refresh`, а на GitHub — Run workflow.

Папка публичная, OAuth-токен не требуется. Чтобы поменять источник, измени `publicUrl` в конфиге или задай переменную репозитория **Settings → Secrets and variables → Actions → Variables → `YANDEX_DISK_PUBLIC_URL`**. Можно читать подпапку через `sourcePath`, например `/Работы`.

На GitHub изображение и сайт скачиваются заново на каждой сборке. При ошибке Диска, неверной кодировке, повторяющемся адресе или оборванной загрузке workflow останавливается **до публикации**, опубликованный сайт остаётся прежним. Локально тоже сохраняются предыдущие успешные данные и сборка; новые данные сначала собираются во временных файлах. Чтобы удалить работу с сайта, убери её папку из источника или задай `Публиковать: нет`, затем запусти обновление.

Сайт использует относительные ссылки, поэтому работает и в корне домена, и по адресу GitHub Pages вида `/DesignPortfolio/`.

Документация: [публичные ресурсы Яндекс Диска](https://yandex.ru/dev/disk-api/doc/ru/reference/public), [публикация Pages через Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [расписание Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
