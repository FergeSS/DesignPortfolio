# Портфолио из Яндекс Диска

Статический сайт с медиа на Яндекс Диске. Ежедневный скрипт читает публичную папку «РаботыСайт», скачивает только описания и сохраняет каталог с путями к изображениям. GitHub Pages размещает страницы, тексты и каталог; сами изображения остаются на Диске и загружаются оттуда браузером по мере просмотра. Node.js 22 или новее, внешних npm-зависимостей нет.

## Запуск

```sh
npm ci
npm run dev
```

Открыть http://127.0.0.1:4173. Остановить сервер — Ctrl+C.

- `npm run sync` — загрузить описания и каталог проектов в `.cache/`, без скачивания изображений.
- `npm run build` — собрать `dist/` из последнего каталога без доступа в интернет. Для просмотра изображений интернет всё равно нужен.
- `npm run refresh` — синхронизировать и, только при успехе, собрать сайт.
- `npm run dev` — проверить Диск при запуске, собрать сайт и открыть его локально. Затем проверять Диск каждые 24 часа, пока сервер работает. При недоступности Диска продолжает показывать предыдущую успешную сборку, если она есть.
- `npm run preview` — показать готовый `dist/` без синхронизации и автоматических проверок каталога.
- `npm test` — проверить загрузку, пагинацию, UTF-8, страницы, сохранность копии при ошибках.

## Папки на Диске

Ссылка уже записана в `portfolio.config.json`. Корень ссылки — сама папка «РаботыСайт», дополнительная папка «Работы» внутри не нужна.

```text
РаботыСайт/
├── Пример1/
│   ├── info.txt
│   ├── cover.jpg
│   ├── 01.jpg
│   └── 02.png
├── Пример2/
│   ├── info.txt
│   └── cover.webp
└── Черновики/             ← полностью игнорируется
```

Названия папок могут быть русскими и содержать пробелы. Одна папка первого уровня — одна работа. Файлы проекта лежат непосредственно внутри неё; вложенные папки проекта не обходятся. Папки `Черновики`, `Drafts` и начинающиеся с точки игнорируются. Файлы в корне тоже игнорируются.

Пустые папки видны на сайте как заготовки с надписью «Нет материалов». Если `info.txt` отсутствует, названием становится имя папки. Отчёт о загрузке доступен по адресу `sync-report.html` относительно главной страницы.

## info.txt

Скопируй `examples/info.txt`, сохрани в **UTF-8** и загрузи в папку проекта:

```text
Название: Айдентика кофейни «Зерно»
Категория: Брендинг
Год: 2026
Порядок: 1
Адрес: zerno
Публиковать: да

Описание:
Текст проекта.

Ещё один абзац.
```

Все поля необязательны. Если указываешь поле, пиши его название как в примере. Метаданные идут **до `Описание:`**, всё после этой строки считается описанием. HTML отображается как обычный текст. Порядок — целое число, меньшие числа выше; без поля работа получает 9999. При одинаковом порядке работы сортируются по названию. Категории автоматически становятся фильтрами на главной.

Для совместимости можно использовать `info.docx` с теми же полями: читается основной текст документа Word, оформление не переносится. DOCX, переименованный в `info.txt`, тоже распознаётся по содержимому; в отчёте появится подсказка. В папке должен быть только один файл описания: `info.txt` или `info.docx`. Старый бинарный `.doc`, RTF и произвольные ZIP не поддерживаются.

Если в файле вообще нет полей из примера, весь текст становится описанием, а название берётся из имени папки. Так можно начать с обычного текста и добавить поля позже.

`Адрес` — уникальные строчные латинские буквы, цифры и дефисы. Например, `zerno` создаёт страницу `projects/zerno/`. Без адреса используется стабильный идентификатор, полученный из пути папки; переименование папки изменит такой адрес. Чтобы ссылки сохранялись при переименовании, укажи `Адрес` явно. Также принимается поле `Slug`.

`Публиковать: нет` полностью исключает работу из сайта, JSON и отчёта. Публичная ссылка на сам Диск при этом всё равно даёт доступ к его содержимому: для приватных черновиков держи папку вне «РаботыСайт».

## Изображения

Поддерживаются JPG, JPEG, PNG, WebP, GIF, AVIF. Один файл `cover` с любым из этих расширений — обложка, остальные идут по имени с учётом чисел: `01`, `02`, `10`. Обложка тоже отображается в галерее проекта. Если `cover` отсутствует, для карточки используется первое изображение. Клик по изображению открывает увеличенный просмотр; Escape закрывает его.

Обложки загружаются напрямую с Диска через его уменьшенные превью, только когда карточки приближаются к видимой области. Если превью недоступно, используется оригинал. На странице проекта загружаются его видимые изображения в исходном размере. Поэтому большие оригиналы лучше заранее подготовить для веба.

Сборка не скачивает изображения и не копирует их в `dist/`: размер оригиналов не расходует лимит GitHub Pages. В каталоге хранятся только пути, названия, размер и версия файла. Подписанные ссылки не записываются в сборку: браузер получает свежую ссылку публичного API при показе изображения, а при ошибке запрашивает её повторно. OAuth-токены не используются.

Когда изображение уходит достаточно далеко за экран, через 1,5 секунды незавершённая загрузка отменяется и `src` удаляется. Размер блока сохраняется, чтобы прокрутка не прыгала. При возвращении изображение загружается снова. Окончательным освобождением памяти и HTTP-кэшем управляет браузер; гарантировать немедленное удаление всех байтов из памяти нельзя.

В случае ошибки есть повторная загрузка и ссылка на папку Диска. Доступность и скорость изображений теперь зависят от Яндекса и соединения посетителя. Публичные скачивания могут ограничиваться при большом числе обращений: [правила Яндекс Диска](https://yandex.ru/support/yandex-360/customers/disk/web/ru/share/sharing-to-me). Проверка каталога выполняется раз в сутки, но запросы изображений происходят во время просмотра сайта. При удалении файла или закрытии доступа на Диске он может перестать отображаться сразу, даже если каталог ещё не обновился.

Поддержка видео пока не реализована. Текущий каталог и интерфейс обрабатывают изображения.

## Внешний вид

Тёмный стеклянный интерфейс, глянцевый логотип FD с лёгким парением и расхождением букв при прокрутке на неподвижном фоне, мозаика с исходными пропорциями обложек и разные световые фоны страниц проектов. На подробной странице есть выбор изображения, сведения о файле и полноэкранный просмотр; Escape закрывает просмотр, стрелки переключают изображения. Карточки при прокрутке плавно поднимаются, увеличиваются и выходят из лёгкого размытия с небольшой задержкой между соседями. После полного ухода за экран появление повторяется. При наведении сохраняются цветное свечение и блик за курсором, при нажатии на телефоне — короткий отклик. Обложка плавно раскрывается в работу и возвращается в плитку с сохранением позиции и фильтра; адрес страницы и кнопки истории браузера продолжают работать. Во время загрузки оригинала используется уже показанное превью. Шапка с названием и контактами закреплена при прокрутке. Буквы используют отдельные PNG с прозрачностью, без тёмных подложек. Настройка уменьшения движения в системе отключает анимации. Jost хранится в проекте вместе с лицензией. Название бренда и контакты задаются в `portfolio.config.json`, оформление — в `src/style.css`. Мозаика автоматически запоминает пропорции загруженных обложек; сами изображения в локальное хранилище не записываются.

## Публикация на GitHub Pages

Workflow `.github/workflows/pages.yml` готов для ветки `main`:

1. Отправить проект в репозиторий GitHub.
2. В **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**.
3. Запустить **Actions → Update portfolio and deploy Pages → Run workflow** или сделать push в `main`.

После подключения GitHub сайт обновляется **раз в сутки, в 04:17 по Москве (01:17 UTC)**. Push в `main` и ручная кнопка Run workflow тоже запускают обновление. Запуски по расписанию могут задерживаться; в публичных репозиториях расписание отключается после 60 дней без активности. Настройка workflow сама по себе не публикует текущие локальные файлы — нужен push.

Открытая страница сама подхватывает новую опубликованную версию примерно в течение минуты. Для этого браузер читает маленький файл `site-version.json` с самого сайта. Если изменилось только время проверки, страница не перезагружается. Во время просмотра увеличенного изображения обновление откладывается. Если текущий проект удалён, браузер возвращается на главную.

Таким образом, достаточно добавлять и редактировать материалы на Диске: после ближайшей ежедневной проверки сайт обновится автоматически. Для срочного обновления локально можно выполнить `npm run refresh`, а на GitHub — Run workflow.

Папка публичная, OAuth-токен не требуется. Чтобы поменять источник, измени `publicUrl` в конфиге или задай переменную репозитория **Settings → Secrets and variables → Actions → Variables → `YANDEX_DISK_PUBLIC_URL`**. Можно читать подпапку через `sourcePath`, например `/Работы`.

На GitHub при сборке загружаются только метаданные и описания. При ошибке синхронизации каталога, неверной кодировке или повторяющемся адресе workflow останавливается **до публикации**, опубликованные страницы остаются прежними. Локально тоже сохраняются предыдущие успешные данные и сборка; новые данные сначала собираются во временных файлах. Это защищает каталог и страницы, но не создаёт резервную копию медиа на сайте. Чтобы удалить работу из каталога, убери её папку из источника или задай `Публиковать: нет`, затем запусти обновление.

Сайт использует относительные ссылки, поэтому работает и в корне домена, и по адресу GitHub Pages вида `/DesignPortfolio/`.

Документация: [публичные ресурсы Яндекс Диска](https://yandex.ru/dev/disk-api/doc/ru/reference/public), [публикация Pages через Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [расписание Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
